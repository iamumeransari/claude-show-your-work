# Known issues

What's broken or unproven, and what was fixed and why, so nobody has to find these again. Update this file when an issue is fixed or found.

## Open

- **Ghostty's painting isn't verified headless.** The pty harness (`testing-and-debugging.md`) sees every placement Claude Code sends, not what Ghostty draws. Resizing, Large and playback need a look on screen before a release.
- **The side-by-side view doesn't use fitted copies.** `SplitView` sizes the paired clip with `sizeFor` and never calls `fitCopy`, so after a window narrows it can be cropped the way single videos were.
- **The resends after a resize can be cancelled.** `resized` schedules them from inside a render, and Claude Code may cancel a superseded render's sleeps (`ui.render: superseded`). A playing video corrects itself on its next frame; a paused one may stay at the old placement until it's drawn again.
- **The cell size wobbles mid-drag** (16.19 then 16.05 px in one drag): Ghostty reports a pixel size and a column count that briefly disagree. It causes an extra box change or two, not a wrong final size.
- **A video at a size not seen yet takes a few seconds** to get its copy (chunks are cut again at the new width). Until then the next best copy is drawn: whole but smaller, or, if every copy is too wide, the narrowest one, slightly cropped.
- **Large: a brief crop at a new window size.** A size with no fitting copy yet draws the nearest one until its copy is cut, about 0.4 s for a video now (`rescaleVideo` cuts only the chunk on screen) and 0.1–0.3 s for a still. If every copy is too wide, that moment is cropped. `picture_wider_than_box` right at a size's first appearance is this.
- **Enlarged stills pile up in the temp folder.** Each time a picture is prepared, its enlarged copy is written under a new name (`<name>-<generation>-w<width>.png`), so the same picture shown again adds another (seen: about 400 files, many 7.6 MB). Only the week-old cleanup removes them. Name them by the source and width instead, like `widenStill` does.
- **The frame trim fix (0.7.0) isn't tested by hand yet.** `TRIM_SH` must be run in a temp folder with spaces in its name (see `testing-and-debugging.md`); the session that changed it couldn't run scripts that delete.
- **Fitted copies are Large only.** In Standard a picture wider than a shrunken box is drawn as before (Standard's box changes little, so this was never seen). If it shows up, extend `isFitted` rather than making Standard re-cut on every resize.
- **Disk:** in Large, a picture can have up to nine copies, and a video a frame folder per width. Frames stay within the 500 MB cap (`TRIM_SH`), stills within the week-old cleanup.
- **Other terminals and systems are unproven.** Whether Warp, WezTerm, kitty and Konsole report their tty size in pixels (as Ghostty does) is assumed, not measured; the plugin only scales a cell under 10 px wide. Linux and Windows haven't been run with Large or resizing.
- **Reported: the terminal feels sticky with pictures on screen, and scrolling up sometimes jumps back.** Seen in the user's Ghostty while temporary debug logging (a `sips` call and a log write on every redraw) was in the local copy; removed. Measured headless afterwards with five pictures and a playing video: each scroll step answered in 1–26 ms, no jump back while scrolled up or during playback. If it's still seen on screen, the cause is Ghostty decoding pictures sent again on scroll back (`mayBeDropped`), or a box growing when a sharper copy arrives (the content height changes under the scroll position).

## Fixed in 0.7.0 (not yet released)

| Bug | Since | Cause | Fix |
|---|---|---|---|
| Video plays in slow motion or freezes, and its buttons seem dead (#14) | 0.6.x | Frames were cut on one thread, and chunks two or more ahead at macOS's utility priority. Real footage (72 Mbit/s 1080p H.264, keyframes up to 3 s apart) cut slower than real time on one thread (4.9 s per 2 s chunk), and with every core busy macOS starved the utility-priority cut outright; playback reached that chunk, waited on it, and froze while still showing Pause | Chunks are cut with ffmpeg's default threads at normal priority, one at a time (1.4 s per 2 s chunk, about 310 MB peak). A 33 s clip of that footage, played at once: 8.9 fps with 3 stalls before, 11.1 fps with none after; with all 8 cores busy, frozen at frame 96 before, 11.1 fps after. Priority can't go above normal without root. Playback also keeps real time now: when frames aren't ready it holds and then skips to where the clock is, and owes frames by elapsed time, not ticks (ticks run late, which alone played at about 0.9×): 1.00× measured idle and with 8 and 16 busy processes |
| Pictures draw as empty boxes in Orca (#16) | 0.6.x | Orca reads a kitty `t=f` file only from a temp folder or the terminal's worktree (none in its floating terminal), and only up to 2 MiB; it refuses others silently. Stills converted to PNG often pass 2 MiB, and wide-enough PNGs draw from `.show-your-work` | In every terminal but Ghostty and kitty, `pngSource` draws from a temp-folder copy under 2 MB, and a video chunk with a frame over 2 MB is cut again in 256 colours (PR #17; see `showing-images.md`). Checked on screen in Orca by the reporter |
| A video shown moments ago reads "This preview has expired" after a resize | 0.6.x | A resize switches the player to a copy whose frames near the playhead aren't cut yet. The render cut them itself, and Claude Code cancels a draw's processes once the next draw replaces it, which a resize does many times, so the cut died and the video counted as expired with its source still on disk | Expired only when the source is gone; otherwise the copy's poster is drawn and the missing chunk is cut outside the draw (`event: recut`). Reproduced headless with two `show_video` calls and a drag: 4 expiries per run before, 0 after |
| Frame folders deleted while a copy was being cut into them ("ffmpeg could not read … could not open file"); frames cut again and again | 0.6.x | `TRIM_SH` measured the whole temp folder (stills too) against the 500 MB frame cap, so with enough stills every trim emptied the frame cache | Only frame folders count; a folder changed in the last two minutes is never trimmed |
| Large: a video cropped for seconds (up to ~30) after the window changed size | 0.7.0 dev | A copy at a new width prepared the whole clip again: probed it, looked for a lead-in, cut its first 5 s, then the part on screen (2.5–8 s measured, cancellations made it longer) | `rescaleVideo` reuses the clip's facts and cuts only the chunk on screen (~0.4 s); a small fallback copy is made as soon as a video is shown |
| Cells measured twice their size; pictures made twice as wide as needed; in Large, boxes half the space | 0.6.0 | The tty size, already in pixels, was multiplied by the screen's scale | Scale only a cell under 10 px wide (`cellOf`) |
| After going back to an earlier window size, the picture stayed at the last size | 0.6.x | `generation` was made from the box, so it repeated, and Claude Code skips a source it already sent | Never-repeating `boxGeneration` (`resized`) |
| Pictures the wrong shape after dragging a window edge for a while | 0.6.x | A measure cancelled mid-drag set the cell to null, so boxes fell back to guessed 2:1 cells | A cancelled measure keeps the last size (`measureCells`) |
| Videos never got sharper copies in the tour; `$.process.run(sips) aborted` errors | 0.6.x | Work started inside a render is cancelled when a newer render replaces it, and a playing video re-renders constantly | Start copies 300 ms after the draw; forget a cancelled one so it's asked again |
| A video made for a wide window was cut off after the window narrowed | 0.6.x | Ghostty crops a picture bigger than its box | Draw the widest fitted copy (`fitCopy`, `COPY_WIDTHS`) |
| A playing video stayed small in a bigger box (or cropped in a smaller one) | 0.6.x | The play timer holds its own video object and kept sending the old copy's frames | Match every frame to the player's chosen copy (`syncCopy`) |
| A frame swap in flight during a resize landed at the old size | 0.6.x | The swap was placed with the old columns and rows | Resend 250 ms after the box settles, and again 750 ms later |
| Picture size fell back to Standard after `/reload-plugins` | 0.7.0 dev | Module state resets on reload, and `session.start` may not run | `ensureSettings` reads saved settings once per plugin load |
| Tour: "This preview has expired" for frames cleaned from the temp folder | 0.6.x | Missing frames were taken for a missing original | `recutFrame` cuts them again |
| Tour: Next could be pressed before the demo appeared | 0.6.x | The bar showed while the demo loaded | Only "Loading the demo…" until it's ready |
| Warp drew a grid of boxes instead of the picture after Turn on pictures (#10) | 0.6.7 | Claude Code's `Image` draws only with kitty Unicode placeholders, which Warp, WezTerm and Konsole don't paint; forcing pictures on just exposed the placeholders | Those terminals get the notice from session start; Turn on pictures is gone and its profile line is removed |
| tmux: "Shown" but a blank gap, even with `allow-passthrough on` (#15) | 0.6.x | Claude Code writes pictures unwrapped inside tmux, so tmux drops them | With `CLAUDE_CODE_FORCE_TERMINAL_IMAGES=1`, the plugin forwards Claude Code's picture commands wrapped for tmux (`tmux.ts`); without it, a notice with the restart command |
| The show-your-work hint never reached Claude on Team and Enterprise logins (#13) | 0.6.x | Claude Code's `cc-plugin-sec-default` guard skips mods' `prompt.compose` hooks | The hint goes as `prompt.submit` context: once per session, after a compaction, and when pictures stop drawing |
| Many installs stuck on old versions with no error reported | 0.5.x | Checks failed before reporting (CLI not on the hook's `PATH`) and still counted for the day | `update_check` event, CLI found via the login shell, failed checks retried |
